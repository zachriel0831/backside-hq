HQ 第一批 .NET 10 升級｜更動與風險清單

整理日期　2026 年 11 月 13 日

已完成的更動

  • 通訊錄新增 .NET 10 站台。提供各店傳真表與員工餐廳分機表，沿用 /Home/FaxView、/Home/Restaurant。員工首頁、兩個後台及業務 API 繼續由原有站台提供。
  • 保留通訊錄舊書籤與中文編碼。兩個新站頁面使用 UTF-8；原有 /Areas/tel/fax.htm、/Areas/tel/restaurant.htm 保留 Big5。傳真表的工作表、頁籤與樣式隨站台發布，兩版各列文字、合併儲存格與表內連結已比對一致。
  • Word 轉 HTML 共用同一份轉換程式。既有 HQBackSite 繼續在 .NET Framework 4.7.2 處理上傳與預覽，同一份轉換程式也已在 .NET 10 編譯，8 個轉換案例全數通過，含圖片、合併表格、連結及中文特殊字元。
  • 修正首頁與舊後台選單的載入順序。沿用既有 jQuery 套件，調整書籤、電話查詢、輪播和側欄按鈕的初始化。在 jQuery 1.9.1、3.4.1 的正常與延遲載入測試中，通過數從 2/8 增至 8/8。

兩版都已重現的問題

  • 首頁電子報。舊電子報來源無法讀取時，首頁會停止載入後面的網站連結。以可用的測試電子報回應驗證時，後續區塊可正常顯示。
  • ISO 文件明細。管理者移除一筆明細後，員工端已看不到該筆；管理者重開同一張表單，仍會看到已移除的列。

11 月 12 日本機回歸共比對 56 個相同網站案例，通過數從 48 增至 54，原先通過的 48 案均維持通過。另加新站專屬 6 案，升級後合計 60/62。

正式切換前的風險

  • 網址導向錯站。若把整段 /Areas/tel/ 導向新站，各店電腦室聯絡頁 system.htm 和傳真活頁簿 fax.xls 會回傳 404。IIS 應只轉送上述四個入口及所需傳真附檔，並實測舊書籤、活頁簿下載與切回原站。
  • 員工通訊資料的存取範圍。新站本身沒有登入檢查。正式開放前，須確認員工內網或 IIS 的存取限制同時涵蓋兩張通訊表與可直接開啟的附檔。
  • 重新發布可能清除歷史附件。原 HQ 的資料夾發布設定會清除目的目錄。若與使用者上傳目錄共用，舊文章仍可能顯示連結，但檔案已被移除。發布前先備份，並在發布與回復後各下載一份歷史附件。
  • 正式身分與跨庫資料。本機使用隔離帳號與資料庫。正式切換前，需用不同部門帳號驗證登入、撤權後的可見資料，以及員工庫與電子報跨庫讀取。
  • 後台編輯與檔案權限。原 UEditor 子站若缺少對應的共用元件及版本設定，兩版都會在讀取設定時回傳 HTTP 500。正式 IIS 也需驗證上傳及 Word 預覽目錄權限，以歷史文件核對圖片、連結與預覽。
  • 外部資源可用性。品牌圖示網址兩版相同；11 月 13 日從本機讀取時，外部閘道回傳 HTTP 403，拒絕規則仍待確認。另在分類查詢頁，外部 AJAX 套件未載入時，送出查詢會只剩結果表格；富文字編輯器的工具列也需在員工網路驗證。
